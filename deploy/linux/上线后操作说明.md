## 1. 先确认服务器部署方式

新的 Node16 升级脚本支持 Node 16.20.2+、systemd 219+，保留服务器当前服务账户与组，不要求存在 `www-data`。网站必须在 `/var/www/focusource`、服务叫 `focusource.service`、Node 在 `/usr/bin/node`、Nginx 反向代理到本机 4173、环境文件 `/etc/focusource.env`。自定义服务 drop-in 会触发预检停止。

根据服务器截图已确认 CentOS 7、Node 16.20.2、systemd 219、服务 active、运行账户 root、工作目录正确。为避免升级时改变未知的文件访问权限，本次保留 root 账户；迁移到独立低权限账户仍是后续待办，不能视为已完成。Node 16 与 CentOS 7 已停止官方安全维护，此次适配不改变这一点。

在腾讯云轻量服务器终端检查：

```bash
systemctl status focusource --no-pager
systemctl show -p WorkingDirectory -p User -p ExecStart focusource
/usr/bin/node --version
systemctl --version
systemctl show focusource -p EnvironmentFiles
```

截图显示终端由宝塔提供，不影响已确认的 systemd + Nginx 架构。Docker、PM2、其他路径或自定义 systemd 配置，请先调整部署方案，不要直接执行本升级脚本。无需开放公网 4173；公网由现有 HTTPS/Nginx 提供。已有证书及 Nginx 配置不由此脚本修改。

## 2. 上传并安装升级

先在腾讯云创建实例快照，再上传 `focusource-node16-upgrade-20261021.tar.gz` 到服务器 `/tmp/`。请勿使用旧版 v1/v2。此包只带代码和操作说明，不带本地 `data/`、图片、上传视频或账户密钥，不会用本地内容覆盖线上内容。它仅将错误格式的 Google Ads ID 清空，其他设置保留。

先在服务器设置管理员密码，至少 16 个字符，建议用密码管理器生成 24 位字母数字密码，不要在聊天中发送密码：

```bash
sudo nano /etc/focusource.env
```

保留其他已有内容，并确认包含：

```text
HOST=127.0.0.1
PORT=4173
NODE_ENV=production
TRUST_PROXY=1
ADMIN_PASSWORD=这里填写你独立生成的强密码
```

注意：真正设置的密码不能用上面的中文占位文本。不要复制 `.env.example` 覆盖现有环境文件。

解压到单独的新目录，升级会短暂停站，开始前自动备份内容、询盘、上传文件、环境文件和旧代码：

```bash
NODE16_UPGRADE_DIR=$(mktemp -d /tmp/focusource-node16-XXXXXX)
tar -xzf /tmp/focusource-node16-upgrade-20261021.tar.gz -C "$NODE16_UPGRADE_DIR"
sudo bash "$NODE16_UPGRADE_DIR/focusource-node16-upgrade-20261021/deploy/linux/upgrade-launch.sh" --check
```

看到 `Preflight passed` 后，在同一终端执行正式安装：

```bash
sudo bash "$NODE16_UPGRADE_DIR/focusource-node16-upgrade-20261021/deploy/linux/upgrade-launch.sh"
```

脚本会安装自启动和每日备份定时器，遇到错误会尝试回滚已备份代码与服务并启动，不能保证所有故障都自动恢复；每日备份配置及无效 Ads ID 清理不会自动回滚。应查看日志并按后面的回滚说明处理。升级成功仍需公网验收。

```bash
sudo systemctl is-enabled focusource
sudo systemctl is-active focusource
curl --fail http://127.0.0.1:4173/healthz
sudo systemctl list-timers focusource-backup.timer --all
sudo journalctl -u focusource -n 50 --no-pager
```

## 3. 网站线上验收

运行只读审计，不会登录、提交询盘或改网站数据：

```bash
cd /var/www/focusource

```

结果中 `summary.failed` 应为 0。账户配置状态单独列出，自动检查通过不代表 Google 验证完成。若失败先排查失败项，再继续推广。

用手机和电脑分别打开首页、复合打包带页、钢丝扣页，检查菜单、图片、视频播放及横向溢出。点击询价，应打开表单并带入产品；检查 WhatsApp 目标号码与邮箱是否正确。用你自己的邮箱提交一条标注“上线测试”的询盘，再登录 https://www.composite-strapping.com/admin.html，核对询盘和状态保存。不要在公网运行 `tests/smoke.js`，它是会修改数据的本地测试。

## 4. 配置询盘邮件

邮件服务采用 Resend HTTP API，无需安装 npm 依赖。前提是你可以使用 Resend，并能配置发件域名 DNS。Gmail 可以作为收件箱，不能直接当作未经验证的域名发件地址。

1. 在 Resend 添加自己控制的发件域名，例如 `notify.composite-strapping.com`，按控制台要求增加 DNS 记录，等待显示验证通过。
2. 创建发送邮件所需 API key；只保存在服务器环境文件，不写后台、Git 或聊天。
3. 用 `sudo nano /etc/focusource.env` 添加以下内容，替换示例：

```text
RESEND_API_KEY=替换为你创建的密钥
INQUIRY_EMAIL_FROM=FOCUSOURCE <website@notify.composite-strapping.com>
INQUIRY_EMAIL_TO=alexyuqd@gmail.com
```

收件地址是当前网站公开联系邮箱，可按实际业务改成你的销售邮箱。发件地址必须属于已验证的域名；遵循控制台给出的 SPF/DKIM 设置，避免新建多个相互冲突的 SPF 记录。

```bash
sudo chmod 600 /etc/focusource.env
sudo systemctl restart focusource
```

提交一条新的测试询盘，确认后台记录为 `Email sent`，并在收件箱和垃圾邮件中核对内容，点击回复应指向买家邮箱。`sent` 表示服务商已接受发送，不保证最终进入收件箱；还需检查 Resend 投递/退信记录。失败最多重试 8 次，退避重试最长间隔一小时，首次尝试超过 23 小时停止。后台出现 `failed` 时核对域名、密钥、额度、网络和服务商日志；当前没有手动补发功能，可从后台联系客户。

网站有基础限流和隐藏反垃圾字段，不能保证拦截全部垃圾询盘。密钥更换后重启服务生效。

## 5. Google Search Console 和统计

Search Console 推荐添加域名资源 `composite-strapping.com`，在域名 DNS 控制台添加 Google 给出的 TXT 值，返回 Google 验证。或者添加网址前缀资源 `https://www.composite-strapping.com/`，选择 HTML 标签，将标签的 `content` 值填入网站后台的 Google Site Verification，不要粘贴整个标签，保存后再验证。

验证通过后提交：

```text
https://www.composite-strapping.com/sitemap.xml
```

使用网址检查工具检查首页、复合打包带页和钢丝扣页，确认 canonical 域名是 `www.composite-strapping.com`。提交不等于立即收录，Google 决定抓取和收录时间。

在 GA4 创建网站数据流，把 `G-...` Measurement ID 填到网站后台 GA4 字段并保存。请检查 GA4 增强型衡量，关闭自动表单互动及可能采集联系方式的自动采集项；本代码不发送表单字段，使用自定义事件统计询盘。未允许统计的访问者不会加载 Google 统计脚本，因此统计数量通常少于实际访问量。

用无痕浏览器打开网站，点 `Allow analytics`，在 GA4 Realtime 中核对访问；提交测试询盘核对 `generate_lead`，点击 WhatsApp、邮箱核对 `whatsapp_click`、`email_click`。再在 GA4 中将 `generate_lead` 标记为关键事件。如果界面名称调整，以当前 GA4 控制台为准。

只有使用 Google Ads 时才配置 `AW-...` 和 conversion label；这两项不能填手机号。只有询盘接口返回成功，才触发询盘转化。统计支持首页、产品页和分类页，页面底部可以修改统计选择。撤回选择会禁用标签并重载页面，不代表清除浏览器内所有已有 Cookie。

## 6. 验证备份并保留服务器外副本

每天服务器本地时间 03:15 执行备份，兼容 systemd 219。先手动执行一次：

```bash
sudo /usr/local/sbin/focusource-backup
sudo ls -lh /var/backups/focusource
sudo journalctl -u focusource-backup -n 30 --no-pager
```

每日归档包含根目录的 `site.json`、`inquiries.json`、`focusource.env`，以及 `public/uploads/`。不包含已删除媒体的回收站或整个代码目录；升级时另存一份旧代码及服务文件。备份包含密码和买家信息，不要放到网站公开目录或 Git。定期通过受控渠道下载到服务器外私有存储，并检查磁盘空间。脚本不自动清理旧备份。

验证归档内容时，将文件名换成真实备份路径：

```bash
sudo tar -tzf /var/backups/focusource/实际备份文件.tar.gz
```

恢复演练先解压到独立私有目录，核对 JSON 和文件，再决定是否恢复线上。不要把整个归档直接解到网站根目录，因为环境文件和 JSON 的归档位置与实际部署不同。

## 7. 升级失败时回滚

升级脚本会显示 `code-before-launch-时间-进程号.tar.gz` 的确切路径，同目录保留对应 `.service`。先查看 `journalctl`。需要回滚时，把下列两个“实际”文件路径替换为同一次升级备份：

```bash
sudo systemctl stop focusource
sudo tar -xzf /var/backups/focusource/实际旧代码.tar.gz -C /var/www/focusource
sudo cp /var/backups/focusource/实际旧服务.service /etc/systemd/system/focusource.service
sudo systemctl daemon-reload
sudo systemctl start focusource
sudo systemctl status focusource --no-pager
```

代码回滚保留当前询盘和上传文件。不要随意恢复旧 `inquiries.json`，否则会覆盖备份后收到的客户询盘。确需数据恢复时，先对当前数据备份，停止服务，解压到私有目录后分别把 `site.json`、`inquiries.json` 安装回 `/var/www/focusource/data/`，上传文件恢复到 `public/uploads/`；环境文件只在必要时单独恢复至 `/etc/focusource.env` 并设为 root 所有、600 权限。数据及上传目录需由实际 systemd 运行账户可写，此服务器目前为 root。数据恢复方案必须考虑增量询盘合并，不能照搬旧快照覆盖。

完成一条完整测试询盘后再引流。核对每款产品真实参数、MOQ、交期、联系方式，及时回复询盘。先观察自然搜索和询盘来源，Google Ads 可等统计和转化验证完成后再安排。若服务器在中国大陆，还应按腾讯云要求核对域名备案状态。
